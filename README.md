# 📂 Problem Sets (PSets)

Below is a breakdown of the skills demonstrated in each completed problem set:

### PSet 1: Credit or Cash
**Focus:** Conditional Logic, Modulo Arithmetic, and Data Validation
* **Description:** Applied C programming and Luhn’s algorithm to determine the validity of a credit card number and identify its issuing company.
* **Relevance to Compliance/QA:** Directly showcases the ability to design and implement **strict data validation rules** and **conditional logic**—essential for KYC verification and ensuring data accuracy in audit records.

### PSet 2: Scrabble
**Focus:** Data Mapping, Scoring Algorithms, and Array Manipulation
* **Description:** Developed a program that calculates the Scrabble score for a word based on a predefined value array, handling different character cases.
* **Relevance to Compliance/QA:** Required meticulous **data mapping and rule implementation** to ensure accurate calculation, mirroring the systematic execution needed for precise quality assurance scoring and metric calculation.

### PSet 2: Readability
**Focus:** String Parsing, Character Counting, and Formula Application
* **Description:** Implemented the Coleman-Liau index to assess the reading grade level of a given text by accurately counting letters, words, and sentences.
* **Relevance to Compliance/QA:** Highlights proficiency in **parsing large text strings** and **applying complex formulas to derived data**, skills crucial for systematic data analysis and report generation from documentation.

### PSet 2: Caesar
**Focus:** Encryption Algorithms, Command-Line Arguments, and Modular Arithmetic
* **Description:** Implemented the Caesar cipher to encrypt text using a key provided via a command-line argument.
* **Relevance to Compliance/QA:** Demonstrates an understanding of **basic encryption and data security principles**, informing my proactive approach to **risk assessment** and the handling of sensitive compliance data.

### PSet 3: Plurality
**Focus:** Algorithm Design, Data Structures, and Voting Simulation
* **Description:** Built a voting program that simulates the Plurality election system, including tallying votes and determining a winner.
* **Relevance to Compliance/QA:** Required careful design of **data structures to track variables** and implementation of **clear, rule-based logic**—directly aligning with the need for structured records and transparent, rule-based decision-making in compliance workflows.
